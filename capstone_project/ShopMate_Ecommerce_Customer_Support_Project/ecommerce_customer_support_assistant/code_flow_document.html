ShopMate Code Flow Guide

E-commerce Customer Support Assistant

1. High-level architecture

The app is a FastAPI backend with a browser chat UI. The frontend posts questions to /api/chat. The backend classifies the user intent, retrieves relevant policy text, invokes mock commerce tools for order and return logic, and optionally asks a Groq LLM to turn retrieved context into a natural-language answer.

2. Request flow

Browser UI → app/static/app.js → POST /api/chat → app/main.py → SupportAgent.answer() → classification + retrieval + tool/LLM handling → JSON response

3. Main code files

  • app/main.py: Creates the FastAPI app, mounts static files, serves the UI, defines the chat endpoint, and exposes health/demo-order endpoints.
  • app/agent.py: Orchestrates the workflow. It classifies user intent, retrieves relevant FAQ passages, handles order/return/refund/escalation logic, and optionally calls Groq.
  • app/knowledge.py: Retrieval layer. Tries sentence transformers first, then falls back to TF-IDF when needed.
  • app/tools.py: Mock business logic for order status, returns, refund policy, and human escalation.
  • app/config.py: Loads environment variables from .env, including model and API key settings.
  • app/static/app.js: Browser-side chat logic to send requests and render replies.

4. Intent and decision logic

The agent checks whether the message is about:

  • order status
  • return requests
  • refunds and payments
  • human escalation
  • general FAQ questions

For order and return actions, it uses the mock data layer instead of a live payment system. For FAQ questions, it retrieves ranked help-center content and optionally feeds it to Groq to produce a final answer.

5. Data layer

The app stores synthetic customer data in the local JSON files under data/:

  • data/faqs.json — FAQ and policy knowledge
  • data/orders.json — synthetic order records
  • data/returns.json — return requests created by the mock system

6. Why the app falls back

If the Groq model call fails, the app catches the exception, writes the error type to the server log, and returns the best retrieved knowledge from the local FAQ store. This keeps the app usable even when the external model is unavailable.

7. Short code explanation

  • app/main.py defines the HTTP layer and API schema.
  • app/agent.py is the core decision engine.
  • app/knowledge.py is the retrieval layer for local RAG.
  • app/tools.py is the fake commerce backend.
  • app/static/app.js handles user interaction in the browser.

8. Summary

This is a compact customer support assistant that combines routing, retrieval-augmented generation, mock product data, and optional LLM-based answer generation. It is ideal for demo use, evaluation, and teaching agent design patterns in a small real project.
